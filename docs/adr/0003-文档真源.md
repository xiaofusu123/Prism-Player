# 0003 文档真源

- 状态：已接受
- 日期：2026-10-09
- 相关：`docs/archive/README.md`、`docs/markdown/设计文档.md`

## 背景

仓库里的文档有**三份内容高度重叠、但互不同步**的副本：

| 位置 | 内容 | 性质 |
|---|---|---|
| `docs/markdown/*.md` | 6 份 | Markdown 重写稿 |
| `docs/docx/*.docx` | 3 份（2 份有内容，1 份 0 字节） | **更早的 Word 手写稿** |
| `docs/txt/*.txt` | 2 份 | 对应 md 的 ASCII-art 版（已删除） |

**它们不是「一份真源 + 两个导出」，而是三份平行副本：**

- `代码规范.docx` 的最后一次内容改动是 `1b1f634`（2026-05-25），而 `代码规范.md` **2026-06-01 才被创建**（`4f63c65`）。时间线是倒的 → docx 不是 md 的产物。
- docx 内部 `docProps/core.xml` 自证是中文版 Microsoft Office Word 人工编辑产物（`<dc:creator>炎杰 周</dc:creator>`、`cp:revision` 21/31、`w:rsidRoot`、`w:proofState`、中文 Word 的 styleId 映射），本机也**没有安装 pandoc**。任何渲染器都不会生成这些。
- 两份 docx 里存在 md 没有的实质内容（`项目计划书.docx` 6 条，含「数据库 E-R 图 + SQL 语句优化」这一条交付要求；`代码规范.docx` 2 处冲突条文）。
- `docs/docx/设计文档.docx` 是 **0 字节**，且**从 2026-05-01 创建之日起就是空的**（`git log --all --follow --name-status` 只有 1 次 `A` + 2 次 `R100`，无任何 `M`；三处 blob 均为 git 空 blob `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391`）。
- 而**同名的 `design` 文档曾经存在过**：`docs/markdown/设计文档.md` 2026-06-01 创建 → 2026-06-04 增至 10,221 B → **2026-06-10 被 `aa3e210` 删除 321 行**。同一个提交新增了 `API接口文档.md`（+700 行），只把其中的 **C API 部分**搬走了，剩下 9 类内容（选型对比表、选型理由、解码管线、Vendor 库设计、设计模式表、安全设计、未来扩展）在其余任何文档里都没有等价物。

同时还有一个更严重的问题：**文档系统性超前于代码**。文档写「已实现」的东西，磁盘上大量是 0 字节文件或只有声明。这不是文档写错了字，而是**没有真源、没人负责对齐**的必然后果。

## 决策

**1. `docs/markdown/*.md` 是唯一真源。** 任何文档内容以它为准；docx 与 txt 都不再是真源。

**2. 两份旧 docx 移到 `docs/archive/`，不删除。**

`git mv docs/docx/代码规范.docx docs/archive/代码规范.docx`、`git mv docs/docx/项目计划书.docx docs/archive/项目计划书.docx`。

不删除的理由：它们带 **md 无法表达的封面页与中文 `Normal.dotm` 样式**，很可能是课程/答辩的 Word 交付材料；删除是破坏性的且没有替代物。归档而不是删除，保留了 Word 交付的历史形态。

同时写 `docs/archive/README.md` 说明「这里的东西已过时、不要再改」，并记下冻结日期（2026-05-25 / 2026-06-01）、Word 独有指纹、以及两处**已被 md 取代**的条文（文件名命名法、`tests` vs `test/`）作为沿革证据。

它们在归档前，**独有内容已全部并入对应 md**：`项目计划书.md` 收了 6 条（`websocketpp→ixwebsocket` 的选型沿革、Dart/Flutter 完整版本串、数据持久化层、逐层开发语言与模块清单、UI 事件驱动、E-R 图与 SQL 优化要求），`代码规范.md` 以 md 为准并记录了 2 处冲突。

**3. 0 字节的 `docs/docx/设计文档.docx` 删除**（`git rm`）。它既不是真源也不是产物，只是一个从 2026-05-01 就没被填过的空占位；同一天还创建过同样 0 字节的 `docs/API接口文档.docx`，后者在 2026-05-20 也被删了。

**4. 从 git 恢复 `docs/markdown/设计文档.md`，并纳入「与代码一致」的修订范围。**

```
git show 01ac42a:doc/markdown/设计文档.md > docs/markdown/设计文档.md
```

恢复后 blob `09a0391ac9e198cefda4e3cf422ee07a1485996b`（10,221 B），与权威版本逐字节一致。文档数从 5 份变成 **6 份**。

**5. `docs/txt/` 整个目录删除（已执行）。**

txt 是 md 的 ASCII-art 版（标题 `PrismPlayer 数据流图` / `PrismPlayer 项目架构`，均标 2026-06-08），逐节比对后确认**零独有信息**：

- `数据流.txt`（21,820 B / 125 行）只包含 `数据流.md` §1/§2/§3 三张时序图的等轴 ASCII 渲染（步骤 1–21、播放控制、Server 端三步）加一个箭头图例；
- `项目框架.txt`（12,767 B / 119 行）只包含 `项目框架.md` 各层的框图，且**把 md 里已有的错误原样照抄**（「27 个 API」「【最完善层】」「9 个虚方法」「`FileTransferManager` / `P2PConnectionManager`」「构建目标 `Prism-client`」「CMake 4.3.2 + Ninja 1.13.2」）—— 它不是另一个信源，而是同一批错误的第二份拷贝。

**字节数比对应 md 大（21,820 vs 4,622；12,767 vs 7,672）曾让人以为里面藏了额外内容，实际只是等轴填充的空格与制表符**：ASCII-art 每行都要用空格补齐列宽，一行的可见信息可能不到字符数的三分之一。这个「体积异常 ⇒ 可能有独有内容」的推断在本次已被证伪，故不再做内容迁移，直接删除。

同时 `数据流.md` 已清掉 5 个非法控制字符（0x07 / 0x0B / 0x0C，来自未转义的 `\a`/`\v`/`\f`，把 `async_decode()`、`restart()`、`flush()`、`` `ffmpeg` ``、`` `vulkan` ``、`` `nlohmann-json` `` 啃掉了首字符），全文已无控制字符（对 `docs/**/*.md` 做过扫描验证）。

**6. Word 交付版将来由 md 生成，不反向维护。**

若还需要 `.docx` 交付物，做法是「装 pandoc（或 `python-docx`）+ 准备 `reference.docx` 模板（要能表达封面页与中文 `Normal.dotm` 样式）+ 写 `md→docx` 脚本」，**从 md 单向生成**。这是一个尚未开工的工单（#48）。

## 后果

**正面**：

- 「文档说的」与「代码做的」有了单一裁决点，任何人发现不一致时知道该改哪一份。
- 归档而不是删除，Word 交付能力没有丢失；同时 `docs/archive/README.md` 挡住了「把旧 docx 当真源读」这条路。
- 恢复 `设计文档.md` 后，选型理由、解码管线、设计模式、安全设计、未来扩展这些**当初做过但没落地的思考**重新可查 —— 这些正是 ADR 的素材来源（见 0004、0005）。

**负面 / 需要注意**：

- **短期内仓库里没有可交付的 Word 文档**。归档的那两份已经过时，新的还没生成。如果近期有答辩/交付需求，必须先开 #48 的生成脚本。
- `docs/archive/` 里的 docx 仍会被搜索引擎、IDE 全文检索以及「随手 `Get-ChildItem`」的人找到，README 只能降低误读概率、不能消除。
- 两份 docx 与 md 的差异是**不可逆**的（docx 内部样式无法还原成 md），所以这次是「提取内容后归档」，不是「转换」。
- **本 ADR 只解决了「谁是真源」，没有解决「真源与代码一致」**。后者是 6 份文档各自的修订工单（#45 / #46 / #47 / #48）。

## 备选方案

- **双真源（md 给工程师、docx 给交付）**：看起来兼顾了两边，实际是这次混乱的成因本身。两份都要人手改，必然漂移。
- **删除两份旧 docx**：干净，但破坏性且不可恢复地丢掉 Word 封面页与中文样式。若将来要交付 Word，只能重做模板。
- **以 docx 为真源，从 docx 导出 md**：docx 是旧版、且缺大部分内容（md 内容约是 docx 的 2–5 倍），等于主动丢掉一半文档。
- **把 docx 用 pandoc 转成 md，一次性反向合并**：本机没装 pandoc；且 docx 的表格数为 0（纯文本行），转换只能产出扁平的段落，还不如人工提取。
- **保留 `docs/txt/`**（把 txt 当第三种「可打印版」）：实测 txt 相对 md 的增量信息是 **0**（见「决策」第 5 条），且字节数反而更大（`数据流.txt` 21,820 B vs `数据流.md` 4,622 B），维护三份副本没有任何收益；更糟的是 txt 会把 md 里已改正的错误继续以「另一份文档」的形式传播下去。
