## 1. 设计目标

PrismPlayer 是一款跨平台音视频播放器，支持本地播放和联机同步播放。

**核心目标**：
- 高性能音视频解码与渲染
- 多客户端实时同步播放
- 跨平台（Windows / Android / iOS）
- 模块化架构，便于扩展和二次开发

> **实现状态**：📐 **仅设计**（目标陈述）。平台现状：`ui/` 是 Flutter 全平台脚手架但仍是官方计数器模板；`client/` 只在 Windows 上构建过；Android / iOS 无任何构建记录。

## 2. 总体架构设计

### 2.1 分层架构

采用 **六层分层架构**，自上而下依次为：

```
UI (Flutter) → FFI (Dart↔C++) → Service (C API门面) → Business (业务) → Engine (编解码) → Adapter (基础设施)
```

| 要素 | 决策 | 理由 |
|------|------|------|
| 分层数 | 6 层 | 职责清晰分离，每层可独立开发测试 |
| 客户端/服务端分离 | Client + Server | 联机播放需要中心化的房间管理 |
| 动态库 vs 静态库 | Engine/Service 用动态库，Adapter 用静态库 | 动态加载和热插拔；基础设施需要内联优化 |

> **实现状态**：✅ **已落地（库形态一致）**。目录六层齐备，CMake 目标的形态与这条决策完全吻合：
>
> | 目标 | 形态 | 层 |
> |---|---|---|
> | `client-adapter` | STATIC | Adapter |
> | `client-engine` | **SHARED** | Engine |
> | `client-service` | **SHARED** | Service |
> | `client-av_sync` | STATIC | Business（AV Sync） |
> | `client-network` | STATIC | Business（Network） |
> | `Prism-server` | EXECUTABLE | Server |
>
> **例外**：Adapter 用静态库的理由（内联优化）成立，但 Engine/Service 用动态库的真实动机是给 Flutter 通过 FFI 加载 —— `ui/lib/ffi/ffi_bridge.dart` 里拼的正是 `build/client/service/libclient-service.dll`。

### 2.2 Client/Server 分离

```
Client (Windows/Android/iOS)          Server (Ubuntu Linux)
     |                                        |
     |  WebSocket / HTTP                      |
     +----------------------------------------+
          房间管理、消息转发、用户认证
```

## 3. Engine 层设计

### 3.1 音频引擎

#### 选型：WASAPI 共享模式 (Windows)

| 方案 | 延迟 | CPU 占用 | 独占性 | 选定 |
|------|------|----------|--------|------|
| WASAPI Exclusive | 极低 | 低 | 独占设备 | ❌ |
| **WASAPI Shared** | 低 | 低 | 与系统混音 | ✅ |
| DirectSound | 高 | 低 | 共享 | ❌ |
| WaveOut | 极高 | 低 | 共享 | ❌ |

**选择理由**：WASAPI 共享模式在延迟和兼容性之间取得最佳平衡，用户播放时仍可听到系统通知音。

#### 跨平台扩展

```cpp
// 当前实现
AudioEngineWasapiShared  // Windows

// 计划扩展 (通过工厂模式)
AudioEngineAAudio        // Android
AudioEngineAudioUnit     // iOS/macOS
```

#### 工厂模式设计

```cpp
// 抽象接口
class AudioEngineFactory {
public:
    virtual std::unique_ptr<AudioEngine> create_audio_engine() = 0;
};

// Windows 平台
class AudioEngineWasapiSharedFactory : public AudioEngineFactory {
    std::unique_ptr<AudioEngine> create_audio_engine() override {
        return std::make_unique<AudioEngineWasapiShared>();
    }
};
```

#### Engine 抽象接口

`AudioEngine` 核心方法：
`init()` | `play()` | `pause()` | `close()` | `set_play_speed()` | `seek(pts, mode)` | `get_sync_info()`

`VideoEngine` 核心方法：
`init()` | `play()` | `pause()` | `close()` | `set_play_speed(float)` | `seek(pts, mode)` | `get_sync_info()` | `get_render_result()`

同步信息结构体：
- `AudioSyncInfo`：current_pts, next_pts, start_time, duration
- `VideoSyncInfo`：current_pts, next_pts, start_time, duration
- `RenderMetadata`：handle, valid, width, height, format, timestamp

> **实现状态**：🟡 **仅骨架**。工厂与抽象接口的骨架已在磁盘上：`client/engine/src/AudioEngineWasapiShared.cpp`（29 行）、`AudioEngineWasapiSharedFactory.cpp`（7 行）、`VideoEngineVulkan.cpp`（32 行）、`VideoEngineVulkanFactory.cpp`（7 行）。**里面没有任何真实的 WASAPI 调用**，`AudioEngineAAudio` / `AudioEngineAudioUnit` 不存在。

### 3.2 视频引擎

#### 选型：Vulkan 渲染

| 方案 | 性能 | 跨平台 | 学习曲线 | 选定 |
|------|------|--------|----------|------|
| **Vulkan** | 极高 | ✅ Win/Android/Linux | 高 | ✅ |
| DirectX 12 | 极高 | ❌ 仅Windows | 中 | ❌ |
| OpenGL | 中 | ✅ | 低 | ❌ |
| Metal | 极高 | ❌ 仅Apple | 中 | ❌ |

**选择理由**：
- Vulkan 是唯一同时覆盖 Windows、Android、Linux 三大平台的现代 GPU API
- 显式资源管理（VkImage → Texture）保证视频渲染低延迟

#### 解码管线

```
MP4/MKV 文件
    ↓ FileAdapter
FFmpeg Demuxer (解封装)
    ↓
├── Video Stream → FFmpeg Video Decoder → AVFrame
│                                               ↓
│                                     Vulkan Texture Upload
│                                               ↓
│                                     GLFW Window Render
│
└── Audio Stream → FFmpeg Audio Decoder → PCM Buffer
                                                ↓
                                     SoundTouch (变速/变调)
                                                ↓
                                     WASAPI 音频设备输出
```

> **实现状态**：🟡 **仅骨架（管线本身尚未开工）**。`VideoEngineVulkan.cpp` 32 行、工厂 7 行，无 Vulkan 初始化、无交换链、无纹理上传。**解码管线里除 `FileAdapter`（也是空壳）以外的每一个环节在磁盘上都没有源文件** —— `client/engine/src/` 下没有任何 FFmpeg 相关文件。
>
> 依赖侧：`vcpkg.json` 的 `client` feature 已声明 `ffmpeg`、`vulkan`、`glfw3`、`soundtouch`、`glm`，但**全仓没有一处 `find_package`** 去消费它们。

## 5. Business 层设计

### 5.1 AV Sync 同步算法

#### 同步策略

```
AudioClock (主时钟) ← 音频不可中断，作为时间基准
       |
       v
VideoClock ← 对比 AudioClock 计算漂移
       |
       ├── 超前 → 等待 (Sleep)
       ├── 滞后 → 丢帧 (Drop Frame)
       └── 同步 → 渲染当前帧
```

#### 同步状态机

```cpp
enum class sync_state {
    UNINIT,         // 未初始化
    CALIBATING,     // 校准中（初始缓冲）
    SYNCHRONIZED,   // 已同步
    AHEAD,          // 音频超前
    BEHIND,         // 音频滞后
    DISABLE,        // 单播放模式（不启用同步）
    ERROR           // 错误状态
};
```

> **实现状态**：✅ **已落地**（`client/business/av_sync/src/` 5 个 `.cpp` 共 323 行：`SyncAlgorithm.cpp` 47 行算 `drift = video_pts - audio_pts`，超 `ahead_threshold_ms` → `SyncAction::WAIT`、低于 `-behind_threshold_ms` → `DROP`、否则 `RENDER`；`CommandDispatcher.cpp` 130 行、`PlaybackStateMachine.cpp` 65 行、`EngineObserver.cpp` 58 行、`SyncFactory.cpp` 23 行）。
>
> **注意状态机名字对不上**：上面这段 `enum class sync_state`（7 态）来自 `practice/AudioDecoder.h:27`，是**音频解码器**的状态机；AV Sync 模块自己用的是 `client/business/av_sync/include/SyncTypes.h` 里的 `SyncState` 与 `SyncAction`。两处不要混。
>
> 另外 `practice/` 目录被 `.gitignore` 第 2 行忽略、**未被 git 跟踪、不在构建中**。

### 5.2 Network 通信设计

#### 协议栈

| 协议 | 用途 | 库 |
|------|------|-----|
| WebSocket | 实时信令（加入/离开房间、播放控制） | `ixwebsocket` |
| HTTP | REST API（登录、房间列表） | `asio` |
| P2P | 文件直传（计划） | `asio` |

#### 异步模型

选择 **ASIO 异步 I/O** 而非传统同步 + 线程池方案：

```
同步+线程池：                    ASIO异步：
[Thread1] → 等待 → 回调        [单线程EventLoop]
[Thread2] → 等待 → 回调        ├── Socket1 ready
[Thread3] → 等待 → 回调        ├── Socket2 ready
浪费线程资源                    └── Timer event
```

**理由**：C10K 问题下单线程异步模型内存/CPU 效率远超多线程同步模型。

> **实现状态**：📐 **仅设计 —— 占位（接口已定义，无实现）**。`client/business/network/include/` 下真有 6 个头（`IAccountManager.h` 39 行、`INetworkObserver.h` 41 行、`IRoomManager.h` 42 行、`ISignalingClient.h` 40 行、`NetworkFactory.h` 22 行、`NetworkTypes.h` 65 行），但 `internal/NetImpl.h` 与 `src/tmp.cpp` 都是 **0 字节**。`ixwebsocket` / `asio` 已在 `vcpkg.json` 声明，无 `find_package` 消费，也没有任何 socket 代码。

## 6. Vendor 库设计

### 6.1 ThreadPool

动态伸缩线程池设计：

```
min_threads (默认2)  ←→  max_threads (默认4)
       |                       |
       v                       v
  [Worker1] [Worker2]  ←→  [Worker3] [Worker4]
       |         |              |         |
       +----+----+      ←→      +----+----+
            |                          |
        TaskQueue (std::queue<function<void*()>>)
```

| 特性 | 说明 |
|------|------|
| 动态伸缩 | 空闲时缩至 min，繁忙时扩至 max |
| 任务队列 | FIFO 队列，支持任意返回值的函数 |
| 线程安全 | `std::mutex` + `std::condition_variable` |

> **实现状态**：✅ **已落地**（`vendor/threadpool/ThreadPool.h` 87 行 + `ThreadPool.cpp` 109 行，`vendor/threadpool/test/` 下 `common.hpp` 75 行、`benchmark_test.cpp` 103 行、`load_test.cpp` 102 行、`stress_test.cpp` 101 行）。
>
> **但它从未被根构建包含过** —— 根 `CMakeLists.txt` 只有 `add_subdirectory(client)` 与 `add_subdirectory(server)`，`build/` 下连 `vendor/` 目录都没有。这是仓库里唯一有完整 GTest 测试的程序，白放着很久了。已立案把它接进根构建与 CTest（见 `docs/adr/0001-分层架构与库形态.md`）。
